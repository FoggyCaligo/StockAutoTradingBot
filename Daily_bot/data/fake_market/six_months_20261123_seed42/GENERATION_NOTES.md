# 데일리봇 가상 시장 6개월 자료

2026-11-23부터 2027-05-22까지의 6개월 구간에 대해 주말을 제외한 130일의 합성 시장을 생성했다. 실제 기록의 마지막 날짜는 2027-05-21이다. 공휴일은 별도로 제외하지 않는다. 모든 날짜와 시각은 한국 시각이다.

- 하루 09:00:00부터 15:19:59까지 종목당 22,800행, 1초 간격이다.
- 매일 5~10종목이며, 전체 1,019종목일과 23,233,200행이다.
- 상위 매수·매도 각 10단계 가격과 잔량, 현재가, 예상가, 틱 체결량·거래대금을 담았다. 한쪽 주문이 소진된 틱에는 표시 호가가 10개보다 적을 수 있다.
- `x=100bp/일`, `n=1bp`, `a=5`, `b=20`, `c=0.1`, `d=1`, 기본 수량 100주, 취소 확률 0.45, 공격적 주문 배율 4다. 기준선이 하루 +1%인 상승 방향 자료다. 상승·하락·횡보를 섞은 균형 자료는 아니다.
- 전체 seed는 42다. 대량 생성을 위해 종목별 독립 난수 스트림을 사용했다. 같은 종목의 기준가는 생성일 사이에 이어지며, 선택되지 않은 날에는 그 종목을 시뮬레이션하지 않는다.
- 가격 결정·주문 체결·취소 엔진은 저장소 커밋 `709aa91e43902a91cdca4a4d304c7ab23a94118f`의 구현을 사용한다. 표준 CLI의 단일 공유 난수 스트림과 추출 순서가 다르므로, 표준 CLI에 seed 42를 입력한 결과와는 다르다. 포함한 재현 스크립트와 설정으로 재현할 수 있다.
- 용량을 줄이기 위해 개별 체결의 주문번호·체결 목록은 제외했다. 백테스트에 쓰이는 필드와 틱 체결량·거래대금은 유지했다. 그래프 HTML과 백테스트 DB는 포함하지 않는다.

## 파일 구성

월별 ZIP은 여러 개의 독립적인 part로 나뉠 수 있다. 분할 압축을 합치는 방식이 아니다. 원하는 기간의 part를 같은 폴더에 각각 압축 해제하면 된다. 각 ZIP 안에 들어 있는 공통 README·스크립트·manifest는 같은 파일이므로 덮어써도 된다.

- `data/YYYY-MM/fake_market_traces_YYYYMMDD_FAKE##.csv.gz`: 날짜·종목별 압축 CSV.
- `manifest.json`: 전체 파일 목록·날짜·종목·행수·기준가·종가·압축 파일 SHA-256.
- `dataset_config.json`: 생성 설정과 전체 종목 선택표.
- `universe.csv`: 날짜별 종목 선택과 예정 행수.
- `daily_summary.csv`: 날짜·종목별 첫 기록·마지막 기록·가격 범위·체결량·거래대금. 가격 범위는 각 초 마지막 체결가를 기준으로 한다.
- `generate_six_months.py`: 동일 자료를 재현하는 생성 스크립트.
- `prepare_replay.py`: 선택 기간의 파일 무결성을 확인하고 CSV를 풀어 재생용 DB를 만드는 스크립트.

## 백테스트에 사용하기

먼저 원하는 기간을 포함한 ZIP part들을 한 폴더에 압축 해제한다. 예를 들어 이 폴더를 `six_months`라고 하고, StockAutoTradingBot 저장소를 현재 폴더에 두었다면 다음과 같이 하루만 DB로 만들 수 있다. 스크립트 실행에는 기존 프로젝트 의존성이 필요하다.

```bash
python six_months/prepare_replay.py \
  --repo StockAutoTradingBot \
  --data-root six_months \
  --start 2026-11-23 --end 2026-11-23 \
  --out work_20261123
```

저장소 루트로 이동한 뒤 위 DB 경로를 실제 위치에 맞춰 지정한다.

```bash
python -m Daily_bot.backtest.replay_refill_threshold \
  --market-source real \
  --db ../work_20261123/replay.sqlite3 \
  --starting-capital-krw 1000000 \
  --refill-min-expected-return 0.90 \
  --ignore-selected-signals \
  --ignore-actual-fill-exits \
  --trend-filter-disabled \
  --out ../result_20261123.csv
```

여기서 `real`은 이미 기록된 DB를 읽는 경로를 선택한다. 지정한 DB 안의 자료는 계속 합성 자료이며 실제 시장 기록으로 바뀌지 않는다. `--logs-dir`는 추가하지 않는다. PowerShell에서는 위 명령을 한 줄로 입력하거나 줄 끝 역슬래시를 백틱으로 바꾼다.

기존 DB 빌더는 `.csv.gz`를 직접 읽지 않는다. 반드시 위 스크립트처럼 압축을 풀거나 직접 CSV로 풀고 사용해야 한다. 현재 백테스트 러너는 전체 trace를 메모리에 적재하므로 6개월 전체를 한 DB로 만들어 실행하는 것은 권하지 않는다. 하루 또는 짧은 구간으로 나눠 실행하고 같은 DB를 전략 A/B 비교에 재사용한다. 날짜별로 따로 실행하면 자본과 세션 상태도 해당 실행의 설정을 따른다. 자동 복리 연결이나 전체 기간 성과 집계는 이 자료에 포함하지 않는다.

## 해석 시 주의할 점

실제 시장 데이터로 보정되지 않은 모형이다. 시가·종가 단일가, VI, 거래정지, 공시·뉴스는 포함하지 않는다. 봇 주문이 가상 체결 엔진에 직접 들어가지는 않으며 봇의 체결 판정은 기존 snapshot replay 방식이다. 1초 기록의 동적 손절 연속 3회는 60초 기록의 연속 3회와 시간적 의미가 다르다. 기존 전략의 호가단위 표와 생성기의 표가 다른 점도 유지된다.

이 자료에서 수익이 났다고 실제 기대수익이 입증되는 것은 아니다. 특히 상승 방향 기준선만 사용했고 호가 잔량과 후속 주문 압력 사이에 생성 모형의 상관관계가 있다. 취약점과 설정 민감도를 점검하는 자료로 활용하고 실제 기록 평가와 함께 판단한다.
