# 데일리봇 가상 시장 백테스트 설명서

이 문서는 가상 호가 시장의 작동 방식과 사용법을 설명한다. 실제 기록으로 하는 기존 백테스트에 더해, 설정한 장세와 무작위 주문으로 합성 시장을 만들고 같은 표준 전략으로 재생할 수 있다. 활용 목적은 장세·유동성·변동성에 따른 전략의 반응과 취약 조건을 확인하는 것이다. 현재 모형은 실제 시장 데이터에 보정하지 않았으므로 합성 시장에서의 수익을 실제 기대수익으로 해석하지 않는다.

작성 기준: 2026-11-23 구현. 표준 진입점은 `Daily_bot/backtest/replay_refill_threshold.py`다.

## 1 작동 방식과 구성 원리

### 1.1 전체 구성

처리는 다음 순서로 진행한다.

1. 장기 방향·시간별 변동·틱별 변동을 합쳐 종목별 주문 기준선을 만든다.
2. 기준선과 최근 체결가의 차이로 매수·매도 주문 압력을 계산한다.
3. 각 호가의 신규 주문·취소·공격적 주문을 발생시키고, 지속되는 주문장에서 체결한다.
4. 체결가와 잔량을 매 틱 `fake_market_traces`에 기록한다.
5. 해당 실행의 trace만 별도 SQLite DB로 가져와 기존 표준 전략을 재생한다.
6. 거래 결과, 비용 반영 보고서, 일중 그래프와 호가 재생 파일을 저장한다.

| 구성 파일 | 역할 |
|---|---|
| `backtest/fake_market.py` | 설정 검증, 기준선, 주문장, 가상 trace 생성, 입력 선택 연결 |
| `backtest/fake_market_viewer.py` | 하루 차트와 틱별 호가를 재생하는 독립 HTML 생성 |
| `backtest/replay_db_builder.py` | CSV를 재생용 DB로 변환. 가상 파일은 명시적인 별도 패턴으로 읽음 |
| `backtest/replay_refill_threshold.py` | 실제/가상 입력 선택과 기존 슬롯·익절 재진입 정책 실행 |
| `tests/test_fake_market.py` | 체결 규칙, 재현성, 실제/가상 입력 분리, CLI 경로 검증 |

위 경로는 백테스트 전용이며 실거래 러너·설정·계좌에는 접근하지 않는다.

### 1.2 종목과 시간의 구성

초기 가격이 1,500원부터 550,000원까지인 가상 종목 `FAKE01`~`FAKE10` 중 매일 5~10개를 고른다. 종목 수를 지정하면 그 개수를 유지하며 종목은 매일 선택한다. 처음 선택되거나 이전 합성 거래일에 선택되지 않았던 종목은 자신이 마지막으로 보유한 합성 기준가를 이어 쓴다. 선택된 종목의 다음 기준가는 해당 일 마지막 합성 체결가다.

한국 시각 09:00 이상 15:20 미만을 하루로 삼는다. 하루 길이 T는 22,800초이며 종목당 기록 수를 t로 설정하면 시간 간격은 `T/t`초다. 기본 t=22,800은 1초 간격이고 t=380은 60초 간격이다. 주말은 건너뛰며 공휴일은 별도 처리하지 않는다. 개장 기준가를 가정하고 연속매매부터 시작한다.

여기서 **시뮬레이션 틱은 시간 간격**이다. 주문 가격이 움직일 수 있는 최소 단위인 **가격 호가단위**는 별도로 처리한다.

### 1.3 장기 방향과 변동을 합치는 원리

P0는 전일 합성 기준가, u는 당일 경과시간, T는 하루 길이다. 단위 bp는 0.01%다.

```text
기준선(u) = P0 × [1 + {x × u/T + H(u) + E(u)} / 10,000]
```

- `x`: 거래일당 기준선 기울기. +100이면 하루 +1%, -100이면 -1%, 0이면 횡보 방향이다.
- `n`: 변동의 기본 크기, bp. 주문 수량과는 별개의 값이다.
- `H(u)`: 매 시간 방향 ±와 시간당 강도 `U(a*n, b*n)` bp를 뽑아, 해당 구간의 시간 길이만큼 누적하는 성분이다.
- `E(u)`: 매 틱 방향 ±와 강도 `U(c*n, d*n)` bp를 독립적으로 뽑아 누적하는 성분이다.

시간별 방향은 09시·10시·11시처럼 한 시간 구간마다 다시 정하며, 변동은 종목별로 독립적으로 생성한다. 구현은 틱 간격으로 시간별 기울기를 적분하는 이산 근사이므로, 거친 시간 간격에서는 시간 경계 근처의 결과도 달라진다.

`n=0`이면 시간별·틱별 성분이 꺼져 기준선은 직선이다. `a=b=0`이면 시간별 성분만, `c=d=0`이면 틱별 성분만 끈다. 기준선은 당일 가격 범위 안으로 제한한다.

**이 선은 주문 흐름을 유도하는 기준선이며 실제 현재가가 아니다.** 현재가는 체결 결과로만 갱신한다. 따라서 x가 양수여도 모든 종목이 상승 마감하도록 강제하지 않는다.

### 1.4 각 호가의 주문과 잔량 변화

기준선과 현재가의 차이를 가격 호가단위로 나눈 뒤 다음 압력 p를 계산한다.

```text
p = tanh[(기준선 - 현재가) / (현재 가격 호가단위 × 3)]
매수 측 방향 계수 s = +1, 매도 측 s = -1
신규 지정가 수량 = max(1, floor[Q × U(0.2, 1.8) × exp(s × p)])
공격적 주문 수량 = floor[Q × M × U(0, 1) × exp(2 × s × p)]
```

Q는 `--fake-base-quantity`, M은 `--fake-market-order-scale`이다. 각 측·각 가격층의 무작위 수량은 각각 뽑는다. 매수·매도 지정가의 접수 순서를 섞고, 두 방향의 공격적 주문 순서도 섞는다. 공격적 주문은 실제 반대편 대기 주문을 소진하며 부족한 잔여 수량은 취소한다.

매 틱 먼저 각 측 표시 상위 10개 호가의 취소 여부를 독립적으로 뽑는다. 취소할 때는 해당 잔량의 10~70%를 무작위로 정해 오래된 합성 주문부터 줄인다. 다음으로 최근 체결가 주변 각 측 최대 10개 가격층에 신규 지정가를 추가한다. 가격 제한에 걸리거나 한쪽 유동성이 소진되면 표시되는 층수가 10개보다 적을 수 있다.

미체결 주문은 다음 틱에도 남는다. 상위 10개 밖의 주문도 보존하지만 현재가에서 현재 호가단위의 60배보다 멀어진 가격의 주문은 만료 취소한다. 따라서 잔량은 매 틱 새로 초기화되지 않고, 추가·취소·체결에 따라 쌓이거나 줄어든다. 각 층에 기본 유동성을 반복 공급하는 구조이므로 현실의 장기 유동성 고갈을 충분히 표현한다고 가정하지 않는다.

### 1.5 체결과 현재가 결정

주문장은 매수는 높은 가격부터, 매도는 낮은 가격부터 처리한다. 같은 가격에서는 먼저 접수한 주문부터 체결하는 FIFO를 적용한다. 매수 가격이 매도 가격 이상이면 먼저 대기하던 주문 가격에서 체결한다. 한 주문이 여러 층을 소진하거나 일부만 체결될 수 있다.

한 틱 안에 체결이 여러 번 발생하면 마지막 체결 가격이 현재가다. 체결이 없으면 직전 현재가를 유지한다. 잔량만 늘거나 취소되는 행위는 현재가를 직접 바꾸지 않는다. 첫 체결 전에는 가정한 개장 기준가를 사용한다.

생성기 가격망은 일반주식용 2천/5천/2만/5만/20만/50만원 경계의 1/5/10/50/100/500/1,000원 단위다. ±30% 가격 범위는 유효 가격망에 맞춘 간소화 규칙이며 신규상장·특수 기준가까지 재현하지 않는다.

**기존 전략의 `Daily_bot/utils.py` 가격 단위 표와 생성기의 표는 다르다.** 기존 전략과의 비교를 유지하기 위해 예상가·목표가 계산 함수는 그대로 사용했다. 정밀한 수익 평가 전에는 두 표의 정합성을 별도로 점검해야 한다.

가격·시간 우선순위와 호가단위의 참고 자료: [한국거래소 매매체결 방식](https://global.krx.co.kr/contents/GLB/06/0604/0604010100/GLB0604010100T3.jsp), [호가와 호가가격단위](https://regulation.krx.co.kr/contents/RGL/03/03010100/RGL03010100T3.jsp).

### 1.6 전략 재생과 체결 엔진의 구분

**가상 시장 엔진의 부분체결과 봇 백테스트의 체결 판정은 별개의 단계다.** 생성기는 합성 참여자들의 주문을 체결해 시장 기록을 만든다. 이후 봇은 완성된 기록을 읽으며 기존 snapshot replay 방식으로 진입·청산을 판정한다. 봇 주문이 생성기의 주문 대기열에 들어가거나 잔량을 소진시키지는 않는다. 봇의 실제 대기순위·부분체결·슬리피지·시장충격을 이 기능으로 검증할 수는 없다.

기본 신규매수 후보 평가 주기는 60초다. 해당 시점은 `scan_candidate`, 중간 틱은 `watch`로 기록한다. 보유 포지션과 동적 손절은 중간 틱도 관측한다. 그래서 1초 기록에서 동적 손절 연속 3회는 60초 기록에서의 연속 3회와 시간적 의미가 다르다. 서로 비교할 때는 관측 간격과 연속 횟수를 함께 맞춰야 한다.

표준 replay의 슬롯·익절 재진입·동적 손절 정책과 기존 수수료·세금 보고 경로를 사용한다. 실거래 코드와 표준 replay 사이의 기존 차이도 유지된다. 예를 들어 표준 replay에는 실거래의 dynamic stop 후 전체 신규매수 차단이 포함되지 않는다.

### 1.7 전략 평가 효과에 대한 판단

다음 평가는 현재 구현을 읽고 내린 작성자의 판단이다.

| 평가 목적 | 현재 기대할 수 있는 효과 | 해석 조건 |
|---|---|---|
| 매수·청산·슬롯 정책의 결함 찾기 | 유용함 | 조건을 고정해 문제를 재현하고 원인을 추적할 수 있음 |
| 상승·하락·횡보 및 변동 강도별 민감도 | 유용함 | 입력 조건과 관측 주기를 일관되게 유지해야 함 |
| 전략 변경안 A/B 비교 | 조건부 유용함 | 같은 합성 DB를 재사용하고 다른 설정은 고정해야 함 |
| 실제 승률·수익률 추정 | 현재 근거가 약함 | 주문 흐름과 시장 분포가 실데이터에 보정되지 않음 |
| 봇의 실제 체결 가능성·시장충격 | 현재 검증 불가 | 봇 주문이 주문장에 참여하지 않음 |

가장 중요한 한계는 **모형과 전략이 공유하는 구조**다. 생성기의 압력 p는 한쪽 지정가 잔량과 같은 방향의 공격적 주문을 함께 강화한다. 데일리봇은 호가 잔량으로 신호를 계산한다. 따라서 이 생성기는 잔량 불균형과 후속 가격 움직임 사이에 전략에 유리한 상관관계를 인위적으로 만들 수 있다. 같은 설정에서 시드를 많이 바꾸는 것은 이 구조적 편향을 제거하지 않는다.

현재 없는 요소는 시가·종가 단일가, VI, 거래정지, 뉴스 충격, 현실적인 종목 간 상관관계, 시간대별 주문 흐름, 실제 취소·신규 주문의 경험적 분포다. 이 모형에서의 실패는 가정한 조건에서의 취약성을 보여 주지만 실제 시장에서도 반드시 실패한다는 판정은 아니다. 성공 역시 실제 수익성의 입증이 아니다.

현실적인 주문장 시뮬레이션 연구도 시장 반응과 실데이터 기반 생성·보정을 별도로 다룬다. 이 문서의 평가는 해당 연구가 이 구현을 검증했다는 뜻이 아니다. 참고: [Coletta 외, Towards Realistic Market Simulations, 2021](https://arxiv.org/abs/2110.13287).

효율 측면에서는 실기록이 쌓이기를 기다리지 않고 특정 조건을 반복할 수 있다. 반면 현재 파일 형식은 크다. 확인한 5종목·1일·1초 간격 실행은 114,000행이며 CSV 약 270.4 MiB, DB 약 350.4 MiB로 두 파일만 약 620.8 MiB였다. HTML은 별도다. 대량 시드 탐색에서는 생성·저장·전체 trace 적재 비용을 고려해야 한다.

평가 가치를 높일 후속 작업의 우선순위는 실제 trace로 스프레드·잔량·변동 분포를 보정하기, 잔량과 후속 주문 압력의 결합을 바꾼 생성 모형끼리 비교하기, 봇 주문을 체결 엔진에 직접 넣기다. 현재의 60초 안팎 snapshot 기록만으로는 틱별 주문·취소율과 대기열 변화를 복원할 수 없으므로 해당 보정에는 더 세밀한 데이터가 필요하다. 이 후속 기능들은 이번 구현에 포함되지 않는다.

## 2 사용법

### 2.1 실행 준비와 기본 실행

저장소 루트에서 프로젝트 의존성이 설치된 Python으로 실행한다. Windows 가상환경을 사용한다면 아래 `python`을 `.\.venv\Scripts\python.exe`로 바꿀 수 있다. 아래 줄바꿈은 Bash 형식이다. PowerShell에서는 한 줄로 입력하거나 줄 끝의 역슬래시를 백틱으로 바꾼다.

기본 가상 시장 백테스트:

```bash
python -m Daily_bot.backtest.replay_refill_threshold \
  --market-source fake \
  --fake-seed 42 \
  --fake-days 1 \
  --fake-stocks 5 \
  --fake-ticks-per-day 22800 \
  --fake-x -100 \
  --fake-n 1 \
  --fake-a 5 --fake-b 20 \
  --fake-c 0.1 --fake-d 1 \
  --starting-capital-krw 1000000 \
  --refill-min-expected-return 0.90
```

이 예시는 5종목, 1초 간격, 기준선 하루 -1%다. `--fake-stocks`를 생략하면 매일 5~10개를 선택한다. `--fake-days 3`으로 여러 날을 생성할 수 있다. 빠른 기능 확인에는 `--fake-ticks-per-day 380`을 사용한다.

**틱 수를 줄이면 같은 시장을 단순히 성기게 기록하는 것이 아니다.** 생성되는 틱별 잡음의 횟수, 신규 주문·취소 횟수, 체결 기회도 달라진다. 380틱 성과를 22,800틱 성과와 동일 시장에서의 결과로 비교하지 않는다.

### 2.2 옵션 표

| 옵션 | 기본값 | 의미 |
|---|---:|---|
| `--market-source` | real | `real`은 기존 DB/실기록 재생 경로, `fake`는 새 합성 시장 생성 후 재생 |
| `--fake-seed` | 42 | 난수 시드 |
| `--fake-days` | 1 | 합성 거래일 수 |
| `--fake-start-date` | 2026-11-23 | 첫 날짜, 한국 시각. 주말은 다음 평일로 이동 |
| `--fake-stocks` | 0 | 0이면 매일 5~10개, 지정 시 5~10 범위 |
| `--fake-ticks-per-day` | 22800 | 종목당 하루 틱 수 |
| `--fake-x` | 100 | 기준선의 하루 기울기, bp |
| `--fake-n` | 1 | 시간별·틱별 변동의 기본 크기, bp |
| `--fake-a`, `--fake-b` | 5, 20 | 시간별 기울기 강도의 하한·상한 배율 |
| `--fake-c`, `--fake-d` | 0.1, 1 | 틱별 변화량 강도의 하한·상한 배율 |
| `--fake-base-quantity` | 100 | 신규 주문의 기본 주식 수 Q |
| `--fake-cancellation-probability` | 0.45 | 각 측 표시 가격층의 취소 확률, 0~1 |
| `--fake-market-order-scale` | 4 | 공격적 주문의 수량 배율 M |
| `--fake-scan-interval-seconds` | 60 | 신규매수 후보 평가 주기 |
| `--fake-output-dir` | 자동 생성 | 해당 실행의 출력 폴더. 지정한 폴더는 비어 있어야 함 |
| `--fake-no-viewer` | 미지정 | 지정하면 HTML 생략 |
| `--starting-capital-krw` | 기존 러너 기본값 | 가상 실험의 시작자본. 예제처럼 명시하는 편이 좋음 |
| `--refill-min-expected-return` | 필수 지정 | 익절 반환 슬롯의 재진입 기대수익률 기준 |
| `--out` | 실행 폴더 내 결과 | 거래 CSV 위치. 관련 일별 보고서도 이 이름에서 파생 |

기존 매매·위험관리 옵션도 전달할 수 있다. 전체 도움말은 `python -m Daily_bot.backtest.replay_refill_threshold --help`로 확인한다.

### 2.3 장세와 변동 조정 예시

2.1의 기본 명령에서 다음 옵션만 바꾼다. 수치는 기능과 민감도를 확인하기 위한 예시이며 실데이터에서 추정한 한국 시장 파라미터가 아니다.

| 목적 | 변경 옵션 |
|---|---|
| 상승 방향 | `--fake-x 100` |
| 횡보 방향 | `--fake-x 0` |
| 하락 방향 | `--fake-x -100` |
| 잡음 없는 직선 기준선 | `--fake-n 0` |
| 시간별 변동만 사용 | `--fake-c 0 --fake-d 0` |
| 틱별 변동만 사용 | `--fake-a 0 --fake-b 0` |
| 변동 규모 확대 | `--fake-n 2` |
| 잦은 취소 상황 | `--fake-cancellation-probability 0.8` |
| 공격적 주문 확대 | `--fake-market-order-scale 8` |

기본 수량 Q를 바꾸면 공급과 공격적 주문이 함께 비례하므로 `--fake-base-quantity`만 줄였다고 반드시 가격 변동성이 커지는 것은 아니다. 취소율과 공격적 주문 배율을 함께 통제해 결과를 확인한다.

같은 모델 버전·설정·시드에서는 같은 CSV를 생성한다. 설정을 바꾸면 주문장 상태에 따라 무작위 추출 경로도 달라질 수 있으므로, 같은 시드를 쓰더라도 모든 외부 조건이 정확히 동일하다고 가정하지 않는다.

### 2.4 출력 확인과 호가 재생

기본 출력 위치는 `Daily_bot/backtest/results/fake_market/<실행시각>/`다.

| 파일 | 확인할 내용 |
|---|---|
| `fake_market_traces_YYYYMMDD.csv` | 매 틱 현재가·전일가·최우선 호가·예상가. `raw_json`에 단계별 잔량, 기준선, 틱 체결량·거래대금·체결 상세 |
| `manifest.json` | 모델 버전·생성 설정·시드·일별 종목·행수·CSV SHA-256 |
| `market_YYYYMMDD.html` | 종목 선택, 하루 체결가와 기준선 차트, 시점 슬라이더, 재생/정지, 10단계 호가 |
| `replay.sqlite3` | 해당 실행의 합성 trace만 저장한 입력 DB |
| `backtest_fake.csv` | 거래별 진입·청산·수량·사유. `pnl_percent`는 비용 전 가격수익률 |
| `backtest_fake_daily_rev.csv` | 기존 수수료·세금을 차감한 일별 손익·수익률 |
| `backtest_fake_trade_fills_audit_daily.csv` | 합성 백테스트 거래 감사표. 실계좌 체결내역이 아님 |

HTML을 브라우저에서 열고 종목을 선택한다. 슬라이더 또는 차트 클릭·드래그로 틱을 고르면 그 시점의 호가가 표시된다. 재생 버튼으로 순차 재생할 수 있다. 외부 서버나 CDN이 필요하지 않다.

성과는 먼저 `backtest_fake_daily_rev.csv`의 비용 후 손익으로 판단한다. 콘솔의 단순 승률·평균 `pnl`만으로 비용 후 수익성을 판단하지 않는다. 무거래 거래일은 현재 일별 보고서에서 행이 생기지 않을 수 있으므로 전체 날짜 수는 `manifest.json`과 함께 확인한다.

### 2.5 같은 시장 기록으로 전략만 비교하기

매번 시장을 생성할 필요는 없다. 한 번 만든 DB를 지정하면 기존 기록 재생 경로에서 그대로 재사용할 수 있다. 아래의 `RUN`을 실제 생성 폴더로 바꾼다.

```bash
python -m Daily_bot.backtest.replay_refill_threshold \
  --market-source real \
  --db Daily_bot/backtest/results/fake_market/RUN/replay.sqlite3 \
  --starting-capital-krw 1000000 \
  --refill-min-expected-return 0.90 \
  --ignore-selected-signals \
  --ignore-actual-fill-exits \
  --trend-filter-disabled \
  --out Daily_bot/backtest/results/fake_market/RUN/comparison_a.csv
```

여기서 `real`은 **기록된 입력을 새로 생성하지 않고 읽는 경로**를 선택한다는 뜻이다. 위처럼 가상 DB를 명시했다고 그 데이터가 실제 시장 기록으로 바뀌는 것은 아니다. 합성 데이터 표시는 그대로 유지된다. `--logs-dir`를 추가하지 않는다.

같은 DB에서 재진입 기준을 0.90에서 1.00으로 바꾸어 보려면 위 명령의 `--refill-min-expected-return 1.00`, `--out .../comparison_b.csv`만 바꾼다. 이 방식이면 입력 시장은 고정되고 전략 차이만 비교할 수 있다. 시드를 달리할 때는 새 시장을 만든 뒤 각각 같은 절차로 비교한다.

이 DB 재사용 방법은 확인한 예시다. 압축 저장, 자동 시드 묶음 실행, 시드별 성과 분포 집계는 아직 별도 기능으로 구현하지 않았다.

### 2.6 실제 기록 모드와 입력 분리

실제 기록 백테스트는 기존 명령을 그대로 사용한다. `--market-source real`은 생략 가능하다.

```bash
python -m Daily_bot.backtest.replay_refill_threshold \
  --market-source real \
  --logs-dir Daily_bot/logs \
  --starting-capital-krw 1000000 \
  --refill-min-expected-return 0.90
```

가상 모드는 별도 파일명 `fake_market_traces_*.csv`와 별도 DB를 사용한다. 실제 기록의 기본 검색 패턴 `market_traces_*.csv`에 자동으로 섞이지 않는다. 가상 생성 모드에서 `--db`, `--logs-dir`, `--use-selected-signals`, `--use-actual-fill-exits`, `--trend-filter-enabled`를 함께 지정하면 오류로 중단한다. 이미 파일이 있는 출력 폴더도 거부한다. 재생성하려면 새 폴더를 지정하고, 재평가하려면 2.5의 기존 DB 읽기 방법을 사용한다.

### 2.7 생성만 하기와 실험 권장 순서

백테스트 없이 시장 기록·차트만 생성할 때:

```bash
python -m Daily_bot.backtest.fake_market \
  --fake-output-dir Daily_bot/backtest/results/fake_market/example \
  --fake-stocks 5 --fake-ticks-per-day 380 --fake-x 0
```

권장 순서는 다음과 같다.

1. 380틱으로 파일 생성·호가 재생·보고서가 정상적으로 연결되는지 확인한다.
2. 22,800틱으로 고정한 뒤 상승·횡보·하락 시나리오를 소수 시드로 실행한다.
3. 같은 DB에 전략 A/B를 적용해 비용 후 손익, 거래 수, 손절 사유와 최악 결과를 비교한다.
4. 변경안 선정에 쓰지 않은 시드와 조건에서도 결과를 확인한다. 같은 모형 안의 새 시드 검증이므로 모형 편향 자체가 해소되지는 않는다.
5. 실제 기록 백테스트로 개선 방향이 유지되는지 확인하고, 실행·체결 측면의 확인은 별도로 수행한다.

현재 replay는 전체 trace를 메모리에 적재한다. 장기간·초미세 틱 실험은 여러 실행으로 나누고, 차트가 필요 없는 반복에서는 `--fake-no-viewer`를 사용한다. 동일 시장에서 전략만 바꿀 때는 DB 재사용으로 생성·저장 비용을 줄인다.
