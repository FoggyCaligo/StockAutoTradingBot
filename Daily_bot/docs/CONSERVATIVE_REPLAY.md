# 표준·보수적 체결 재생과 호가 신호 점검

## 기본 표준 모형 (2026-11-28)

CLI의 기본값은 `--fill-model standard`다. 기존 간이 재생 엔진을 명시적으로
선택하는 이름이며 `--fill-model legacy`와 같은 결과를 낸다.
특정 시장이나 거래소가 보장하는 표준이라는 의미는 아니다.

- 신호 시점 현재가로 전량 매수했다고 가정한다. 30초 이내 후속 호가가 없다는
  이유만으로 매수를 취소하지 않는다.
- 이후 관측 현재가가 목표가 이상이면 목표가로 전량 익절한다. 동적 손절과
  시간 청산은 해당 관측 현재가를 사용한다.
- 마지막까지 남은 포지션은 마지막 관측가로 정산한다(`force_exit_last_trace`).
  이 정산은 실제 청산 체결이 아니며, 자료가 장중에 끝난 경우도 포함한다.
- 매수·매도 수수료 각 0.015%, 매도세 0.18%를 손익 보고에서 차감한다.
  기존 간이 엔진의 회전 현금 계산은 비용 차감 전 금액을 사용한다.
- 주문 지연, 부분체결, 표시잔량 제한, 거래소 대기열을 생략한다.
  드문드문 기록된 자료로 전략을 비교하는 간이 기준이며 실제 체결보다 유리할 수 있다.

전략 임계값·시간·슬롯 정책과 실거래 코드는 변경하지 않는다.
CLI는 선택한 `fill_model`을 출력하고, `net_profit_krw`와 `net_win_rate`는 비용 차감 후
기준으로 출력한다. 기존 `pnl_percent`와 `win_rate`는 비용 차감 전이다.

## 적용 범위

기존 `replay_market_traces`, `replay_dynamic_expect_debounce`, 그리고 이를 사용하는
`replay_refill_threshold` CLI는 `--fill-model conservative`를 명시하면 아래 모형을 사용한다.
시장 생성과 전략의 후보 선정·예상가·손절·슬롯 정책은 분리한다. 실거래 코드는 변경하지 않는다.
이전 결과를 재현할 때는 `--fill-model legacy`를 명시한다. Python 함수 호출은 기존 동작을
보존하며 `execution_config=ExecutionConfig(...)`를 넘길 때 보수적 체결을 적용한다.
다른 독립 실험 러너에 적용됐다고 가정하지 않는다.

## 체결 규칙

- 매수와 매도는 기본 1초 주문 도달 지연 후 저장된 호가에서 평가한다. 신호 스냅샷으로 즉시 매수하는 가정은 기본으로 꺼져 있다. 민감도 비교에는 `--allow-signal-snapshot-buy`를 쓰며, 해당 체결 근거는 `signal_snapshot_depth`로 기록한다.
- 매수는 신호 당시 현재가의 지정가다. 키움 매수 흐름의 기본값에 맞춰 주문 제출 기준 30초에 미체결 잔량을 취소한다. 전량 체결 시 다음 2초 조회 시각에, 부분체결 시 취소 시각에 보유 수량을 확인한 것으로 모델링하고 익절 주문을 제출한다. `--buy-order-timeout-seconds`와 `--buy-fill-poll-seconds`로 변경할 수 있다.
- 이벤트 CSV에서 `fill`은 호가 기반 체결 추정, `confirm`은 모의 체결 확인이다. 취소 이벤트의 `observed_active_quote`가 거짓이면 주문 활성 구간에 평가한 후속 호가가 없었다. 실거래의 주문별 API 응답 시간, 순차 주문 제출 및 취소 처리 시간은 모형에 포함되지 않는다.
- 미체결 매수의 현금과 슬롯을 예약한다. 매수 수수료를 포함해 수량을 계산한다.
- 지연 후 주문 가격이 반대편 호가와 교차하면, 관측된 호가를 가격 순서대로 소진한다.
  기본 참여율은 표시 수량의 10%다. 같은 수량이 계속 보인다는 이유만으로 소비한 유동성을 재사용하지 않는다.
- 대기 지정가는 도착 때 같은 가격의 기존 표시 잔량 뒤에 선 것으로 추정한다.
  순번 진행은 이후 구간의 방향·가격·수량이 있는 `executions`로만 인정한다.
  호가 취소·잔량 감소·현재가의 목표가 접촉만으로 순번을 진행하거나 전량 체결하지 않는다.
- 구간별 체결 테이프가 없는 자료는 기본적으로 수동 지정가 체결을 추측하지 않는다.
  `--aggregate-trade-through`를 명시하면 `tick_volume`과 지정가를 엄격히 넘어선 체결가를 이용한
  근사 진행을 허용한다. 이는 실측 FIFO가 아닌 별도 민감도 시나리오다.
- 5초를 넘긴 관측 공백의 테이프는 대기열 진행에 사용하지 않는다.
- 익절 주문도 지연·부분체결을 적용한다. 손절·시간 청산은 지연 후 매수호가를 소진하는
  유동성 취득 매도로 모델링한다. 실거래의 지정가 재주문 과정을 완전 복제한 것은 아니다.
- 데이터가 끝나도 잔량을 마지막 현재가에 매도했다고 만들지 않는다. 미청산 잔량은 별도로 남긴다.
- 매수·매도 수수료 각 0.015%, 매도세 0.18%라는 기존 재생 가정을 현금에도 적용한다.

1초·10%·대기잔량 1배는 검증된 실측 파라미터가 아니라 보수적 실험의 기본 가정이다.
지연 0/1/3초와 참여율 0.1/0.5/1.0으로 민감도를 비교할 수 있다. 신호 스냅샷 매수를 허용한 경우
주문이 도달할 때 표시잔량이 남아 있다고 가정한다. 봇 주문에 대한 시장의 후속 반응은 모형에 없다.

```bash
python -m Daily_bot.backtest.replay_refill_threshold \
  --refill-min-expected-return 0.90 --market-source real --db /path/to/replay.sqlite3 \
  --ignore-selected-signals --ignore-actual-fill-exits --trend-filter-disabled \
  --starting-capital-krw 1000000 --fill-model conservative --out /path/to/result.csv
```

`real`은 이미 저장된 DB를 읽는 경로이며, 그 DB에 가상자료가 들어 있어도 같은 방식으로 재생한다.

## 결과 해석

`*_execution_events.csv`에는 제출·취소·개별 부분체결과 근거가 기록된다. 기존 감사 CSV도
실제 재생된 부분체결을 사용한다. `*_execution.json`에는 설정, 일별 현금, 미청산 잔량,
최종 매수호가로 평가한 잔량 가치와 평가손익이 기록된다. 평가 가치는 실현 청산대금이 아니다.
기존 거래·일손익 CSV는 매도된 수량의 실현 결과이므로, 미청산이 있으면 그것만 보고 성과를 판단하지 않는다.

## 실거래 주문 이후 호가 재생

키움 실거래 매수는 체결 조회 사이의 대기 시간을 이용해 주문 종목의 호가를 조회한다.
전량 체결을 확인한 경우 익절 주문 제출 후에도 한 번 기록한다. 기록은 기존 SQLite와
`market_traces_YYYYMMDD.csv`에 `buy_order_quote`로 저장된다. 원본 호가와 밀리초 이하
관측 시각, 매수 요청 시각, 브로커 주문 번호, 지정가 및 수량이 남는다. 추가 호가 요청은
기존 API 속도 제한을 공유하며 오류 시 재시도 없이 다음 체결 조회로 진행한다.

기존 스캔은 종목마다 조회 시점이 다르고 매수도 순차 제출된다. 기록된 주문 시각에
맞춰 체결 모형을 검증하려면 저장소 루트에서 다음 명령을 실행한다.

```bash
python -m Daily_bot.backtest.replay_refill_threshold --refill-min-expected-return 0.90 \
  --market-source real --db Daily_bot/bot.sqlite3 --replay-recorded-buy-orders \
  --ignore-selected-signals --ignore-actual-fill-exits --out Daily_bot/backtest/results/recorded_buys.csv
```

이 모드는 주문 후 호가가 한 건 이상 기록된 매수 주문의 시각·지정가·수량을 사용하고
실제 체결 대신 호가 기반 체결 모형을 적용한다. 같은 종목을 모의 보유 중이거나 모의 현금이
부족하면 주문을 건너뛰고 이유를 이벤트 CSV에 남긴다. 매수 제출 이벤트의
`broker_order_id`로 실제 체결 내역과 대조할 수 있다. 기존 자료에는 새 관측이 소급
추가되지 않으며, 호가 사이 체결과 수동 지정가의 거래소 대기열은 여전히 제한적으로 관측된다.

## 2026-11-24 호가 신호 비교

실측 16일·117,657행과 최신 ordinary-bull의 8일·53종목·일·1,208,400행을 확인했다.
가상자료 전체 3개월을 검사한 것은 아니다. 양쪽에 같은 10호가 예측기, 양측 1.0→0.0 가중치,
매도 목표 1틱 차감을 적용했다. 09:30~11:30의 `scan_candidate`만 60초 이상 띄워 앵커로 사용했다.
미래 가격은 10/60/300초 이후 첫 관측이며 목표 시각에서 최대 3초까지만 허용했다.
실측의 중복 시각 4,257행을 정리했고 같은 시각이면 스캔 관측을 우선했다.

0.30% 초과~0.71% 이하 신호 구간의 평균 현재가 변화:

| 이후 시간 | 실제 평균 | 실제 표본 수 | 가상 평균 | 가상 표본 수 |
|---|---:|---:|---:|---:|
| 10초 | 0.0000% | 2 | +0.0870% | 336 |
| 60초 | −0.0511% | 19 | +0.0942% | 336 |
| 300초 | −0.0635% | 97 | +0.0921% | 336 |

실측 표본은 희소하고, 날짜·종목·시장 국면·틱 비율이 달라 편향의 크기나 통계적 확률로
해석할 수 없다. 10초 실측 2개로 방향성 결론을 내리지 않는다. 가상시장의 우호적 반응이
보이지만 실전 공정성을 입증하거나 반증한 것은 아니다. 중간호가 수익률도 별도로 JSON에 남겼다.

확인한 가상 앵커 6,360개의 최대 신호는 0.6834%로 진입 기준 0.71%에 못 미쳤다.
실측에는 0.71% 이상 신호가 있지만 60초 후 가격을 허용 오차 내에 연결할 수 없었고,
300초 후 연결은 12개였다. 운영 진입 구간의 직접 비교는 아직 성립하지 않는다.

종목 수만 늘리는 것은 신호 기회를 늘리는 조치다. 호가 간격·잔량·가격대의 분포 자체가
현실과 다르면 진입 신호를 보장하지 않는다. 임계값 통과나 수익률을 목표로 생성기를 조정하지 않고,
미사용 실측 자료의 신호 빈도·강도·조건부 미래 수익률과 호가 분포를 먼저 맞춰야 한다.

현재 생성 세션은 **09:00:00~15:19:59, 22,800초**다. 15:30까지의 전장 자료가 아니다.
마감 단일가와 개장 단일가, VI, 갭, 종목 간 공통 요인은 아직 구현하지 않았다.
연속매매를 단순히 10분 연장해 단일가 구간을 대체하지 않는다.

재현 도구는 `python -m Daily_bot.backtest.check_signal_realism --help`,
수치와 출처는 `backtest/calibration/signal_realism_20261124.json`에 있다.

## 검증

이번 변경의 체결·재생·가상자료·스윕·신호 검사 관련 테스트는 83개 통과했다.
전체 Daily_bot 테스트에서 발견한 14개 실패는 수정 전 소스 스냅샷의 같은 테스트에서도 재현됐다.
기존 실거래 기록·손절 관련 실패이며 이번 체결 변경으로 해결했다고 주장하지 않는다.

기존 생성자료는 Git 배포를 중단하고 `data/fake_market/`를 추적 제외했다.
원본 가상자료나 대용량 조각을 다시 커밋하지 않는다.
