# 무거래 원인과 신호 현실성 보정

2026-11-28 조사. 수정 전 기준은 원격 `main`의
`f4903973c490be396409c13609d6eb5734a3c56c`다.
거래 수나 가상 수익률을 높이는 것이 아니라 실제 입력과 계산의 정합성을 확인했다.

## 130일 전체의 직접 원인

| 항목 | 결과 |
|---|---:|
| 전체 거래일 | 130일 |
| 진입 기준을 넘는 신호가 없던 날 | 107일 |
| 실제 무거래일 | 107일 |
| 진입 신호가 있던 날 | 23일 |
| 그중 실제 거래가 발생한 날 | 23일 |
| 신호는 있었지만 무거래였던 날 | 0일 |

이 자료에서 무거래일의 직접 원인은 진입 신호 부족이다. 예산·슬롯·체결 제한이
107일을 추가로 막았다고 설명할 근거는 없다. 적격 스캔 97행은 23일에 모여 있고,
보유·손절 후 재진입 제한 등 때문에 각 행이 독립 매수로 이어지는 것은 아니다.
기존 진단 집계는 09:30 이상 11:30 미만이며 replay는 11:30도 포함한다.

근거는 `dailybot_mixed_0001_results.zip`의 전체 `daily_results.csv`, `all_trades.csv`,
manifest 및 실행 로그다. 3월 원본 ZIP의 515,020행도 별도로 읽고 진입 스캔을 재계산했다.

## 확인한 계산 결함: 서로 다른 호가단위

생성기는 현행 일반주식 호가단위를 쓰지만 공통 `utils.get_tick_size`는 예전 가격 구간을
썼다. 1,500원/15,000원/150,000원에서 생성기는 1/10/100원, 공통 계산은
5/50/500원이었다. 예상가 내림과 목표가 1틱 차감에 과도한 단위가 적용됐다.

같은 3월 호가를 고정한 비교에서는 진입 스캔 26,620행 중 7,986행에서 틱이 달랐지만,
틱 표만 맞춘 적격 신호는 1건에서 1건으로 같았다. 이 결함의 존재와 무거래 대부분의
원인이라는 주장은 구분해야 한다. 실제 저장 자료 2026-09-10의 407개 진입 스캔은
같은 비교에서 7건에서 8건으로 바뀌었다.

수정:

- 공통 일반주식 틱을 2,000/5,000/20,000/50,000/200,000/500,000원 구간으로 통일.
- 생성기는 공통 함수를 그대로 참조해 두 구현이 다시 달라지지 않도록 함.
- 가격대 경계도 한 틱씩 이동. 예: 2,000원에서 한 틱 아래는 1,999원.

이 공통 수정은 실제 신호·목표가·틱 거리에도 영향을 준다. 진입 임계값, 슬롯 정책,
주문 허용 설정은 바꾸지 않았고 실제 주문은 실행하지 않았다.
ETF/ETN/ELW 및 과거 제도는 별도 검증 대상이다. 0001년은 가상 시간축이다.

## 생성 분포의 문제와 보정 범위

기존 모형은 양쪽 10개 호가에 비슷한 크기의 유동성을 반복 보충한다. 누적 잔량이
비슷해져 예상가가 현재가 근처에 머물기 쉽다. 3월 첫 거래일의 가중 잔량 불균형
99백분위는 약 0.340, 실제 저장 스캔 예시는 약 0.873이었다. 한 날짜의 예시 비교이며
시장 전체에 대한 추정치는 아니다.

10개 고정 시작가격과 촘촘한 호가 간격도 가격 대비 틱 비율과 예상가 상단을 제한한다.
종목 수만 늘리면 이런 분포 차이가 자동으로 사라지는 것은 아니다.

보정 기능은 다음과 같다.

- 실제 호가의 가중 `log(매수잔량/매도잔량)` 변동 폭을 추정한다.
- 종목·거래일별 첫 스냅샷을 쓰고 종목 해시로 학습/홀드아웃을 분리한다.
- 관측의 매수 쏠림 중앙값은 합성 방향성에 넣지 않는다. 독립적인 평균 0 충격을
  지정가 유동성에만 적용하고 미래 기준가나 손익을 보지 않는다.
- 시작가격도 학습 스냅샷 가격대에서 표본추출한다. 홀드아웃 가격은 사용하지 않는다.
- 20개 가상 종목을 지원한다.
- `--fake-depth-calibration`을 지정해야 보정이 적용된다. 기본 비교 시나리오는 유지한다.

포함된 예시는 2026-09-10의 서로 다른 종목 384개 중 학습 305개, 홀드아웃 79개를
사용한다. 후보 선택과 관측 시점에 제한된 초기 보정이다. 지속성 0.995/초는 시나리오
가정이다. 스냅샷만으로 추정한 값이 아니다. 호가 간격·뉴스·시장 충격·조건부 후속 수익까지
현실과 같다고 검증한 상태도 아니다.

## 재현

저장소 루트에서 실행한다. 운영 로그는 읽기 전용으로 쓰고 결과는 별도 경로에 저장한다.

```bash
python -m Daily_bot.backtest.diagnose_no_trades \
  --input Daily_bot/logs/market_traces_20260910.csv \
  --out /path/to/real_entry_diagnostic.json \
  --calibration-out /path/to/depth_calibration.json
```

CSV/CSV.GZ/ZIP 모두 지원한다. `--trades`로 거래 CSV를 주면 신호는 있으나 거래가 없는
날을 표시한다. 정확한 보유·슬롯·재진입·현금 상태는 전체 replay로 확인해야 한다.
저장된 기대수익률은 이전 계산식의 값일 수 있어 현재 코드로 원시 호가를 다시 계산한다.

```bash
python -m Daily_bot.backtest.replay_refill_threshold \
  --market-source fake --fake-profile ordinary-bull \
  --fake-depth-calibration Daily_bot/backtest/calibration/depth_dispersion_20260910.json \
  --fake-stocks 20 --fake-days 1 --fake-no-viewer \
  --fake-output-dir /path/to/new_empty_run \
  --refill-min-expected-return 0.90 --starting-capital-krw 1000000
```

기본값, 잔량만 보정, 가격대도 보정, 20종목을 미리 지정한 시드 901/902에서 비교한다.

```bash
python -m Daily_bot.backtest.validate_depth_profiles \
  --calibration Daily_bot/backtest/calibration/depth_dispersion_20260910.json \
  --out /path/to/depth_profile_validation.json
```

이는 10초 스냅샷의 작은 1일 시나리오 실행 검증이다. 새 6개월 성과나 실전 기대수익률이
아니다. 기존 6개월 표도 이번 수정으로 전 구간을 다시 백테스트한 수치로 덮어쓰지 않는다.
