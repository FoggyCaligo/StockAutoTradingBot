# 사용자의 협업 맥락과 작업 완료 기준

기준일: 2026-11-28. 이 문서는 사용자가 요청한 개발 협업 지침이다.
사용자의 모든 대화나 사생활을 복원한 프로필이 아니다. 현재 요청과 현재 코드가
이 요약보다 우선하며, 바뀐 선호는 확인된 범위에서 갱신한다.

## 가장 중요한 기대

사용자는 코딩 에이전트가 작업을 스스로 이어 가는 협업을 원한다.
“이런 문제가 나왔다”는 진단은 중간 결과다. 수정이 허용된 작업에서는 원인 조사,
구현, 실제 실행, 검증, 요청된 Git 반영까지 연결해서 수행한다.
사용자가 매번 “그럼 고쳐 줘”, “다시 실행해 줘”, “이어서 해 줘”라고 말해야 하는
흐름을 줄인다.

이미 요청하거나 승인한 범위의 다음 단계는 다시 허락받지 않는다.
새로운 전략 선택, 명시적 보존 지시와 충돌하는 변경, 실제 주문 실행,
파괴적인 Git/데이터 조작처럼 범위가 달라지는 경우에만 필요한 결정을 묻는다.
사용자가 “원인부터”, “분석만”, “기존 러너 유지”라고 말하면 그 구체적인 제한을 따른다.

## 작업 중 문제를 만났을 때

1. 실제 저장소·브랜치·설정·실행 명령·입력 파일을 확인한다.
2. 실행 가능한 재현 또는 입력 단계별 탈락 근거를 만든다.
3. 코드 결함, 환경 결함, 데이터 부족, 의도된 전략 조건을 구분한다.
4. 요청 범위에서 확실한 결함을 수정하고 같은 입력/조건으로 재검증한다.
5. 문제가 남으면 관련 경로를 더 조사하고, 이미 가능한 대안 작업을 완료한다.
6. 권한이나 외부 자료 때문에 정말 막힌 부분만 구체적으로 남긴다.

예를 들어 가상자료에서 거래가 없으면, 진입 시각과 `scan_candidate`, 실제 호가,
호가단위, 예상가 재계산, 임계값, 예산/슬롯/당일 재진입 제한을 순서대로 조사한다.
0건이라는 문구만 반환하지 않는다. 반대로 거래 수를 늘리기 위해 진입 임계값을
임의로 낮추거나 수익이 나올 때까지 시드/자료를 고르지 않는다.

## 의사소통

- 한국어로 결과와 의미를 먼저 설명하고 필요한 수치와 근거를 붙인다.
- 추상적인 계획보다 실제 변경, 실행 결과, 확인 가능한 파일/커밋을 선호한다.
- 긴 작업은 현재 확인된 사실과 다음 검증을 간단히 공유한다.
- 전체 집계와 일부 로그/샘플을 구분한다. 중간 추정이 틀렸으면 바로 정정한다.
- “수정했다”, “통과했다”, “올렸다”는 각각 파일 변경, 실행된 검증, 실제 원격 반영에
  근거가 있을 때만 쓴다.
- 현재 환경에 없는 파일이나 과거 대화가 필요하면 연결된 원본을 먼저 찾는다.
  사용자가 이미 제공한 정보를 다시 요구하거나 없는 상태를 추측으로 채우지 않는다.

## 데일리봇의 평가 원칙

사용자는 전략이 손실과 거래비용을 포함해 지속적으로 수익을 낼 수 있는지 알고 싶어 한다.
단기 수익 화면이나 성공적인 가상 시나리오를 장기 성과로 해석하지 않는다.
비교 시 설정과 입력을 잠그고 바뀐 요소의 영향을 분리한다.

- 표준 replay와 실거래의 차이(현재가 전량 체결, 지연/부분체결/대기열 생략 등)를 밝힌다.
- 세금·수수료 차감 전/후 수익, 계좌 자본 대비 수익, 거래당 수익을 구분한다.
- 무거래일을 포함한 전체 거래일 평균을 제공한다.
- 자본 고정과 복리를 구분하고, 포지션이 남으면 평가손익을 누락하지 않는다.
- 소수 거래로 승률·장기 기대수익·실전 유사도 퍼센트를 확정하지 않는다.
- 신호 현실성은 가격 경로뿐 아니라 호가 가격 간격, 가격대별 틱 비율,
  잔량 불균형 분포, 신호 빈도, 조건부 후속 움직임, 체결 가능성으로 확인한다.
- “0.71% 신호가 발생한다”와 “그 가격에 체결돼 수익이 난다”는 별도 검증 대상이다.

## Git과 작업 이력

현재 사용자가 지정한 저장소·브랜치 정책을 확인한다. 다른 프로젝트의 dev/main 정책을
이 저장소에 임의로 적용하지 않는다. 원격 반영 요청은 실제 commit/push 확인까지 진행한다.
공유된 코드와 문서는 재현 가능한 상태로 남기되, 운영 DB와 가상 대용량 자료는 소스와 분리한다.

현재 브랜치를 모른 채 pull/reset/checkout하지 않는다. 사용자 변경과 운영 자료를 보존한다.
자동 승인 심사가 작업을 거부하면 다른 엔드포인트로 같은 거부 작업을 우회하지 않는다.
가능한 수정/검증을 완료하고 정확한 거부 사유와 적용 가능한 산출물을 제공한다.

## 다른 Codex 환경에서도 사용하기

이 저장소의 `AGENTS.md`가 이 문서를 읽도록 연결되어 있다. 새 세션에서 저장소를 열어
현재 지침을 확인한다. 사용자 PC의 전역 설정을 이 문서가 자동으로 바꾸지는 않는다.

여러 프로젝트에 공통 적용하려면 [전역 지침 예시](CODEX_GLOBAL_AGENTS_TEMPLATE.md)의
일반 협업 부분을 기존 Codex home의 `AGENTS.md`와 검토·병합한다. 기존 파일을 통째로
덮어쓰지 않는다. 기본 위치는 `~/.codex/AGENTS.md`이며 `CODEX_HOME`을 따로 지정했으면
그 디렉터리를 사용한다. `AGENTS.override.md`가 있으면 그 지침도 확인한다.

공식 동작 설명: https://learn.chatgpt.com/docs/agent-configuration/agents-md
이 문서는 지침을 제공하며 모델의 모든 행동이나 대화 기억을 보장하지 않는다.
