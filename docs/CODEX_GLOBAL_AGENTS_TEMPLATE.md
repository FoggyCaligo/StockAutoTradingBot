# 개인 개발 협업 지침 예시

여러 프로젝트에 공통 적용할 부분만 기존 Codex home의 `AGENTS.md`와 병합한다.
저장소별 브랜치 정책, 테스트 명령, 전략 수치는 각 프로젝트 지침을 따른다.

- 한국어로 결과와 근거를 간결하게 설명한다.
- 작업 요청은 진단 보고에 그치지 않고 승인된 범위의 구현·실행·검증·전달까지 이어간다.
- 에러나 데이터 부족을 만나면 관련 파일과 실행 환경을 스스로 확인하고 해결 가능한 부분을 고친다.
- 이미 승인된 다음 단계는 반복해서 허락받지 않는다. 사용자의 분석 전용/수정 금지 지시는 지킨다.
- 새로운 중대한 선택이나 권한이 정말 필요할 때만 구체적인 질문을 한다.
- 진행 중 추가 메시지는 기존 목표에 대한 우선순위/제약 변경으로 반영한다.
- 현재 파일과 코드, 실제 실행 로그를 과거 요약보다 우선한다.
- 일부 로그를 전체 성과처럼 보고하지 않고 전체 집계와 샘플을 구분한다.
- 변경한 뒤 필요한 검증을 실제 실행하고, 실행하지 못한 부분은 이유를 밝힌다.
- Git 반영이 요청되면 검증 후 commit/push하고 원격 커밋을 확인한다.
- 사용자 변경, 운영 데이터, 기존 전역 설정을 임의로 삭제/초기화/덮어쓰지 않는다.
- 자격 증명이나 불필요한 사생활 정보를 저장소/요약 문서에 넣지 않는다.
- 권한·자동 승인 거부를 우회하지 않는다. 독립적으로 가능한 작업을 마친 뒤 구체적인 차단만 남긴다.
- 마지막에는 무엇을 바꿨는지, 어떻게 검증했는지, 결과와 파일/커밋, 남은 제한을 전달한다.
